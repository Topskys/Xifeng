# 延迟预算（硬约束）

本文件是端到端延迟的权威额度表。任何新增处理 MUST 在此表登记并占用额度，否则不得合入。

## 指标

- **SLO：端到端 P95 < 1500ms**（按下热键 → 文字出现在光标处）
- 度量：`Trace.e2e_ms`，定义见 `../04-reference/metrics.md`
- PTT 模式额外目标：P50 < 800ms

## 额度表

|---|---|---|---|
| 尾点检测 | 0（松键即触发） | ≤240ms | — |

> 它是可选项，配置页明确标注代价。
>
> 冻结包复测（2026-10-30，`--wav fixtures/quality/01.wav`，4.61s 音频）：
> 纠错关 e2e 353ms；纠错开（warmup 1855ms 一次性 + 纠错 693ms）e2e **1047ms**。
> 同包 `--text` 纠错 519ms。详见 `02-guides/packaging.md`。

> 表中 ASR 350ms 是**空载预算**。两档实测：空载 P50 329 / P95 355ms（2026-10-28，TTS 4.49s），
> 带载 P50 485 / P95 648ms（2026-10-28，CPU ~53%）。**接受的双档口径：空载 350ms / 带载 650ms**，
> `bench.py` 的 350ms 阈值只对空载成立，带载时不判 FAIL（见 `bench.py` 的 `BUDGET` 注释与 §当前实测）。
> 2026-10-29 真人录音复测（4.61s，CPU ~39%）落在 512/539ms，符合"带载"档。
>
> 剪贴板兜底只在目标吃不进按键时发生，e2e 额外约 500ms（实测注入段 507ms，仍 <1500ms 硬指标）；
> `auto` 正常路径不碰剪贴板，注入段 28–39ms。

## 强制规则

1. 模型纠错默认关；开启时若 ASR 实测 > 800ms（读 `Trace.ms_asr`）SHOULD 关掉它（当前未自动降级）
2. 语音 > 15s → MUST 分段并行识别
3. 启动后 MUST 执行 warmup（1s 静音空跑全管线；开启纠错时另跑 `correction.warmup()`），消除首包 500ms+ 冷启动
4. 模型常驻内存，MUST NOT 按次加载
5. 新功能若可能超预算，MUST 提供"超时跳过"路径，禁止无降级的同步等待
6. 任何改动导致 P95 退化 >50ms，MUST 在 PR 说明原因或回退

## 2.1 L1 整句润色实测（2026-10-31，M2 首版）

- **模型**：Qwen2.5-0.5B-Instruct Q4_K_M（491MB）+ llama-cpp-python 0.3.36 CPU wheel
  （abetlen wheel 索引；PyPI 源码包在本机编译不过）
- **延迟（8 线程，few-shot 提示词）**：293–905ms（≤30 字）；守卫拒绝/超时退回 L0
- **质量**：few-shot 后才可用——纯指令提示词 0.5B 会跑偏成翻译（实测）；
  术语表注入 prompt 会稀释示例（实测退化），术语由 L0 先行替换，L1 提示词保持纯 few-shot
- **守卫**（G32）：编辑距离 ≤0.35、长度比 0.5–1.6、ASCII token 必须保留、
  拒绝解释性开头；任何一项不过都退回原文
- **默认关**（`model_correct`，配置页「模型纠错」开关）：开着时 e2e 上限 ≈ L0 + 1.5s，
  长句场景可能顶到 P95 1.5s；默认关闭保证基线 P95

## 3. Silero VAD 的实测与取舍（2026-10-30，M1）

- **前向开销**：每 32ms 窗 ~1.2ms；4.6s 真人录音全程 170–213ms（8 线程空闲机）。
  计入 `Trace.ms_vad`。VAD 模式预算表的"尾点检测+切分"按此口径合并。
- **质量门槛未过**：真人 5 句 golden（基线：能量裁剪 CER 0.0%）上，
  Silero 切分+重组 CER 4.8%，Silero 裁剪 3.9–5.7%。两个根因：
  1. Silero 对很轻的起音音节（"这个""会议"的首字）不敏感，边界滞后咬字；
  2. 句中停顿删除/拼接破坏韵律，混排英文（README）解码对边界极度敏感
     （同句 CER 随边界 0%→27% 波动），能量法反而抓得到弱起音。
- **决策**：PTT 路径维持能量裁剪（不动，0.0% 基线）；Silero 切分机制
  （`vad.py` SileroVad + `probs_to_segments`，已单测）**目前只服务配置页的
  「录音段切分」**（默认关，对按住说话的录音再做一次切分/过滤）。
  **免按键连续模式尚未实现**：托盘主循环仍阻塞在 `record_ptt`；该模式必须切段、
  无 0.0% 基线可退化，且应**逐段分别 ASR**（不拼接），并且要先解决与
  AGENTS.md「不录音时禁止占用麦克风」的冲突。
  参数：`pad_ms=150, merge_gap_ms=400, start_prob=0.5, end_prob=0.35`。
- 模型纠错开启时能兜住英文词形，但它默认关且不稳定，**不作为**回接 PTT 的理由。

## 4. 按需开麦的代价（2026-10-30，0.22）

用户要求"不录音就不占麦克风"，所以默认改为**按下热键才 `LiveMic.start()`**，
松开并 drain 后立刻关闭。代价是每次按下有 **95–400ms 的开流静默期**（G23 表 A），
这段音频不存在，抢话会丢句首。

- 该延迟发生在 `t_start` 之前，**不计入** `Trace.e2e_ms`；e2e 硬指标仍是
  "松手 → 出字 ≤1500ms"（实测 P95 582ms，不受影响）
- 交互上的补偿：浮窗/提示先出现，用户看到"录音中"再开口
- 需要消掉这 95–400ms 时显式 `--resident-mic`：启动即开流 + `pre_ms=300` 前置缓冲，
  代价是整个会话期间麦克风保持打开

### 注入（`inject_smoke.py`，2026-10-28，用户交互终端）

目标窗口是**本进程内的 Tk 窗口**，与真实场景（跨进程、记事本/Edge）不同，数字仅作上界参考。

| 用例 | 字数 | chunk | 注入耗时 | 结果 |
|---|---|---|---|---|
| 你好，世界 | 5 | 8 | — | PASS |
| 中文 English 混排 123 | 17 | 32 | 159ms | PASS |
| emoji 😀🎉 也不能乱码 | 14 | 32 | 135ms | PASS |
| 第一行\n第二行 | 7 | 32 | 185ms | PASS |
| 长文本（20 遍） | 184 | 32 | 255ms | PASS |

`chunk=8` 与 `chunk=32` 各跑一轮，**均 5/5**。

结论：
1. 注入成功率 **5/5**（含代理对、换行、184 字长文本）；`CHUNK_UNITS=32` 无需缩小。
2. 耗时**不随字数线性增长**（7 字 185ms vs 184 字 255ms），更像同进程注入的同步开销与系统输入队列抖动，而非分块延迟（184 字 6 批 × 5ms ≈ 25ms）。
3. 软件侧开销可忽略：`snapshot_focus` 0.01ms、`_elevation` <0.01ms、`build_events(184)` 0.07ms —— 时间全在 `SendInput`。
4. 真实跨进程数字 MUST 在 Rust Step 6 重测，禁止据此判定注入预算达标。

结论：

1. **350ms 预算只在空载机器上成立**（329–355ms）。日常带载工况是 460–650ms，**预算必须改成"空载 350ms / 带载 650ms"两档**，否则每次 bench 都会误报 FAIL。
2. `threads` 是双刃剑：空载 8 线程最快，带载 8 线程尾部最差（648ms）。追求尾部稳定用 4（558ms），追求平均用 8。
3. **e2e P95 最坏 649ms ≪ 1500ms**，余量约 57%。**这是默认配置（纠错关）的数字**；
   开启模型纠错后每句 +0.35–1.5s，P95 可能破 1500ms，因此纠错默认关、代价在配置页写明。
4. Python 侧含 GIL 与跨语言边界开销；Rust + PyO3 预计只降不升，但**必须重测**，禁止复用本行数字。
5. 音频为本地 TTS 合成 —— 延迟可信，**识别质量不可替代真人录音**。
6. 机器噪声是最大变量（同一配置 P95 355 ↔ 648）。任何延迟结论 MUST 注明当时 CPU 占用，否则不可比。
