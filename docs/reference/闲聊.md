## 三、延迟预算（1.5s 达标分析）
| 阶段 | PTT 按住说话模式 | VAD 免按键模式 |
|---|---|---|
| 尾点检测 | 0（松键即触发） | ~240ms（静音判定） |
| 音频切片/重采样 | <5ms | <5ms |
| **SenseVoice 推理**（5s 语音，8 核 CPU，int8） | ~350ms | ~350ms |
| 规则纠错 | ~5ms | ~5ms |
| LLM 纠错（0.5B Q4，≤30 字） | ~250ms | ~250ms |
| 键盘注入 | ~10ms | ~10ms |
| **合计** | **≈ 620ms** | **≈ 860ms** |
GPU 环境下 ASR 可压到 100–200ms。**1.5s 余量充足**。配套保障：
- **Warmup**：启动后用 1s 样例音频空跑全管线，消除首包 500ms+ 的冷启动开销；
- **降级策略**：实测 ASR 耗时 >800ms（长句）时自动跳过 LLM 纠错，仅走规则纠错，守住 1.5s；
- 模型常驻内存，不做按次加载。

AI：# 设计更新：光标注入 + 无效语音/文本清理
## 一、更新后的数据流
```
音频流 → VAD切分(双阈值) → 无效段过滤/重组 → SenseVoice ASR → TextPostProcessor → 纠错(L0/L1) → Injector(光标注入)
                │                                  │                │
                ├─ 丢弃<250ms的呼吸/噪音段              ├─ 幻觉黑名单过滤    ├─ 语气词分层剔除
                ├─ 合并<200ms间隙(防拆词)              └─ 空结果→终止      └─ 归一化/停顿→换行(可选)
                └─ 停顿>1.2s标记为分段点
```
新增两个核心模块：**音频级切分过滤**（ASR 前）、**TextPostProcessor + Injector**（ASR 后）。
## 二、无效片段切分（音频级，ASR 之前）
VAD 在 Rust 侧逐 30ms 块输出 speech probability，采用**双阈值滞回**切分：
| 参数 | 默认值 | 说明 |
|---|---|---|
| 触发阈值 | 0.5（连续 3 帧） | 防止瞬态噪声误触发 |
| 结束阈值 | 0.35（连续 8 帧 ≈240ms） | 即静音判定点，直接复用延迟预算里的 240ms |
| 最小说话段 | 250ms | 短于此的段视为咳嗽/呼吸/键盘声，**整段丢弃** |
| 段间隙合并 | <200ms | 两段间隔太近说明是一个字被误切，**合并保留**（防止“识别”被拆成两个字） |
| 段间能量校验 | RMS < 阈值 且 speech_prob < 0.5 | 双重确认是“静音”而非“轻声说话” |
**关键策略——重组而非逐段识别**：过滤后把有效段拼回**单条 PCM**（每段两侧留 60ms 缓冲）再送 ASR：
- ✅ 保持上下文完整，识别准确率不降；
- ✅ 只做一次推理，延迟不变（仍是 ~350ms）；
- ✅ 静音段剔除后，音频更短，推理反而略快。
**可选：停顿→换行**（段落听写模式）：停顿 >1.2s 的位置标记为段落点，此时改为**并行分段识别**（各段同时推理，延迟取最慢段），按段拼接时在标记处插入换行。默认关闭，普通输入靠 SenseVoice 自带标点即可。
## 三、TextPostProcessor（文本级清理，ASR 之后）
纯 Rust 实现，对 ≤200 字文本做正则处理，**<1ms**。
### 3.1 五步管线
```rust
pub struct TextPostProcessor { cfg: PostConfig }
impl TextPostProcessor {
    pub fn process(&self, raw: &str, seg_meta: &[SegMeta]) -> Option<Cleaned> {
        let t = raw;
        let t = self.filter_hallucination(t)?;   // 1. 幻觉/空结果，None→终止不注入
        let t = self.collapse_repeat(t);          // 2. 重复字折叠
        let t = self.remove_fillers(t);           // 3. 语气词分层剔除
        let t = self.normalize(t);                // 4. 空格/标点归一化
        Some(self.final_check(t)?)                // 5. 终检：全空/全标点→None
    }
}
```
**① 幻觉黑名单**：正则表匹配整句（`^谢谢观看$`、`^字幕由.*提供$`、`请不吝点赞.*`等经典 ASR 幻觉），命中即丢弃；单字符重复 **>8 次**折叠为 2 次（“哈哈哈哈”是真实表意，不能全删）。
**② 语气词剔除——三层安全策略**（这是最容易误伤的地方）：
| 层级 | 范围 | 词表 | 默认 |
|---|---|---|---|
| **L1 句首填充** | 字符串开头 | 嗯/嗯嗯/呃/啊/诶/哎/唔/噢/emmm/uh/um | ✅ 开 |
| **L2 句中孤立填充** | 紧邻标点（前是标点或句首，后接标点）的孤立语气词 | 同上 | ✅ 开 |
| **L3 句尾助词** | 句子末尾 | 呀/呢/吧/啦/哦/啊 | ❌ 关 |
> ⚠️ **句尾助词默认保留的原因**：“好啊”→“好”、“走吧”→“走”会改变语气和语义。句尾剔除只作为“深度清理”可选项，并提示用户风险。
> “那个/就是/然后”属于**话语标记但可能是实词**（“把**那个**文件给我”），不进词表，交给 LLM 纠错阶段用 prompt 处理（“删除口头禅，保留实义成分”）。
- **边界安全实现**：只在 `(^|[，。？！、\s]) 填充词 ([，。？！、\s]|$)` 位置删除，绝不删除嵌在词中间的匹配；循环处理到不动点（覆盖“呃，嗯，那个……”连用）；
- **独立语气句策略**：整句话只有“嗯”→ 默认**不注入 + 播放轻微提示音**（大概率误触/清嗓），可配置为“原样注入”。
**③ 归一化**：中英文之间补空格、连续标点去重、句末标点可配置保留/去除（聊天场景常用“不加句号”）、SenseVoice 自带 ITN 可开关（“三块钱”→“3块钱”）。
**统计埋点**：剔除的语气词数、丢弃的音频段数、幻觉拦截次数 → 上报 GUI 统计页。

## 四、光标位置注入
### 4.1 原理
**不需要定位光标坐标**：键盘事件会自动落在前台焦点控件的 caret 处。所以核心问题只有两个——**用键盘事件注入**、**保证注入瞬间焦点还在原窗口**。
**时序设计**：
```
按下热键时刻:   快照焦点 → {hwnd, pid, 线程id, 窗口标题, 窗口类名, 是否提权, 是否控制台}
识别处理中:     用户可能切窗口（<1.5s 概率低但必须处理）
注入时刻:       GetForegroundWindow() == 快照hwnd ?
                ├─ 是 → 正常注入
                ├─ 否 + restore_focus=true → ALT键技巧恢复焦点(SetForegroundWindow被系统限制时的标准解法) → 注入
                └─ 否 + restore_focus=false → 放弃注入 + Toast提示（防串窗误输入）
```
### 4.2 三种注入策略
```rust
pub enum Strategy { Unicode, Clipboard, Auto }
impl Injector {
    fn inject(&self, text: &str, snap: &FocusSnap) -> Result<()> {
        self.ensure_focus(snap)?;
        match self.strategy(snap) {
            Unicode   => self.send_unicode(text),      // KEYEVENTF_UNICODE
            Clipboard => self.clipboard_paste(text),   // 备份剪贴板→写入→Ctrl-V→延时恢复
        }
    }
    fn send_unicode(&self, text: &str) {
        for chunk in text.encode_utf16().collect::<Vec<_>>().chunks(32) {
            for &u in chunk { /* KEYDOWN|KEYUP with KEYEVENTF_UNICODE, u为UTF-16码元 */ }
            thread::sleep(Duration::from_millis(5));   // 防止事件队列溢出丢字
        }
    }
}
```
| 策略 | 实现 | 适用 |
|---|---|---|
| **Unicode 键盘** | `SendInput` + `KEYEVENTF_UNICODE`，UTF-16 码元逐个发送，32 字符/块 | 默认。浏览器/Office/微信/Electron 全兼容，**天然落在 caret**，不动剪贴板 |
| **剪贴板** | 备份→写入→`Ctrl-V`→300ms 后恢复剪贴板 | 控制台类（conhost 对 Unicode 注入支持差）、超长文本（>500 字）、游戏 |
| **Auto** | 窗口类名匹配 `ConsoleWindowClass`/`CASCADIA_HOSTING_WINDOW_CLASS`/mintty → Clipboard，否则 Unicode | 默认策略 |
**换行**：不用 Unicode `\n`（部分应用不识别），发 `VK_RETURN`；聊天软件可配“回车发送/换行”。
### 4.3 边界情况与对策
| 场景 | 对策 |
|---|---|
| 目标窗口已关闭/焦点切走 | 按配置恢复焦点或放弃 + Toast |
| 管理员权限窗口（任务管理器等） | 检测提权标记 → 提示“以管理员身份重启输入法”，否则 UIPI 拦截注入静默失败 |
| 游戏（Raw Input/DirectInput） | Unicode 事件可能收不到 → Auto 策略下对全屏窗口走剪贴板；仍失败则 Toast 并存入剪贴板供手动粘贴 |
| 结果为空（纯静音/纯语气词/幻觉） | **不注入**，播放短促提示音区分成功/失败 |
| 注入耗时计入延迟 | Unicode 注入 50 字 ≈ 10ms，已在预算内；剪贴板路径 +30ms |

总预算 620ms（PTT）/ 860ms（VAD）→ 仍远低于 1.5s。
## 六、GUI 增量
- **配置页**新增“输出”分组：注入方式（自动/键盘/剪贴板）、焦点切换时行为（恢复/放弃）、语气词层级（三档开关 + 词表自定义）、独立语气句策略、句末标点、停顿换行阈值、ITN 开关；
- **统计页**新增：语气词剔除计数、无效音频段丢弃数、幻觉拦截数、注入成功率、**按目标应用**的注入方式分布与失败次数（用于用户排查某个 App 注入异常）；
- **历史页**：展示“原始 ASR → 清理后 → 纠错后”三级对照，每级 diff 高亮，方便用户反馈误删（一键回滚该条规则贡献的统计权重）。
## 七、坑位清单
1. **UTF-16 代理对**：emoji（😀）是两个码元，必须按 UTF-16 码元而非字符发送，否则乱码；
2. **Ctrl-V 时机**：剪贴板写入后需 `EmptyClipboard→SetClipboardData` 完成再模拟按键，加 30ms 间隔，否则粘贴旧内容；
3. **剪贴板恢复**：恢复动作若在目标应用读剪贴板前执行会粘贴失败，恢复延迟须 >500ms 且可关；
4. **VAD 丢弃段边界**：丢弃段两侧必须留 60ms 缓冲，否则字头/字尾爆破音被切掉导致误识别；
5. **语气词正则**：`呃` 必须排除 `qwertyuiop` 等英文场景（英文输出中 "er" 是正常单词），中文判定仅作用于含 CJK 的输出。

# 架构与进程模型
本文件描述 Xifeng 的进程划分、模块归属与技术选型理由。变更架构前 MUST 先读本文件并同步更新本文件。
## 进程模型
| 进程 | 实现 | 职责 | 崩溃策略 |
|---|---|---|---|
| ime-service | Rust (tokio) | 热键、音频采集、VAD、PyO3 推理、后处理、注入、模型管理、IPC 服务端 | 自动重启 1 次/分钟内；状态从磁盘恢复 |
| ime-gui | Tauri 2 | 统计/模型/配置/历史/关于 五页 + IPC 客户端 | 独立崩溃不影响输入功能 |
两个进程 MUST NOT 共享内存以外的状态。一切交互走 `ipc-protocol.md` 定义的 JSON-RPC。
## ime-service 内部模块
| crate/模块 | 职责 | 关键依赖 |
|---|---|---|
| ime-core | 管线状态机、Trace 打点、降级决策 | tokio, crossbeam |
| ime-audio | cpal 采集 16k/mono、环形缓冲、RMS 推送 | cpal |
| ime-vad | Silero VAD v5 直跑（Rust ort）、双阈值切分、段重组 | ort |
| ime-infer | PyO3 嵌入；ASR(SenseVoice ONNX) 与 LLM(llama-cpp-python) | pyo3, numpy |
| ime-post | TextPostProcessor：幻觉/语气词/归一化 | regex, regex-lite |
| ime-correct | L0 混淆集 + L1 LLM 纠错编排 | — |
| ime-inject | 焦点快照、SendInput/剪贴板注入 | windows, enigo, arboard |
| ime-registry | 模型清单、下载校验、ArcSwap 热切换 | reqwest, sha2, arc-swap |
| ime-ipc | Named Pipe / Unix socket JSON-RPC 服务 | tokio |
## 线程模型
```
主线程        ─ tokio runtime（IPC、模型下载、GUI 事件）
音频线程      ─ cpal 回调，仅做入队（禁止任何阻塞调用）
VAD 线程      ─ 30ms 块消费，Rust 直跑 Silero，输出段事件
推理线程      ─ Python 解释器所在线程（GIL 持有者），消费 PCM 队列
注入线程      ─ SendInput 序列发送（含 5ms/chunk 间隔 sleep）
```
约束：
- Python 解释器在启动时于推理线程初始化一次，之后 MUST NOT 迁移线程（PyO3 要求）
- 音频回调中 MUST NOT 持锁等待、MUST NOT 调用 Python
## 数据流（一次输入）
```
热键按下 → 采集(16k i16) → [VAD 切分+过滤] → 段重组 PCM
  → Python ASR → TextPostProcessor → L0/L1 纠错 → Injector(光标)
  → Trace 汇总 → IPC 事件 → GUI 统计
```
## 技术选型（已定，变更需评审）
| 点 | 选型 | 理由摘要 |
|---|---|---|
| ASR | SenseVoice-Small ONNX int8 | 中文强、自带标点/ITN、CPU RTF≈0.07 |
| VAD | Silero v5（Rust ort） | 30ms 块 <1ms，不进 Python |
| 纠错 | Qwen2.5-0.5B GGUF Q4 + 混淆集 | 30 字 ≈250ms，可降级 |
| 桥接 | PyO3 嵌入 | 零序列化开销；备选独立进程见 gotchas#G1 |
| GUI | Tauri 2 | 与主程序同栈、体积小 |
```

# 延迟预算（硬约束）
本文件是端到端延迟的权威额度表。任何新增处理 MUST 在此表登记并占用额度，否则不得合入。
## 指标

| 阶段 | PTT 模式 | VAD 模式 | 超额处理 |
|---|---|---|---|
| 尾点检测 | 0（松键即触发） | ≤240ms | — |

| TextPostProcessor | <1ms | <1ms | — |
| L0 规则纠错 | <5ms | <5ms | — |

| 注入（50 字键盘） | ~10ms | ~10ms | 剪贴板 +30ms |

4. 模型常驻内存，MUST NOT 按次加载

# 管线状态机与打点

## 状态机
```
Idle ──按键/单击──▶ Recording ──松键/静音240ms──▶ Decoding
                        │ Esc                       │
                        ▼                           ▼
                     Cancelled                  Correcting
                                                    │
                              ┌─────────────────────┤
                              ▼                     ▼
                          Injecting              Dropped(无效)
                              │
                              ▼
                          Idle（结果/错误事件 → GUI）

- VAD 模式下 Recording→Decoding 由静音 240ms 触发（参数见 vad.md）
- 60s 强制截断 → Decoding，截断处记录 Trace.truncated=true
## Trace
```rust
// crates/ime-core/src/trace.rs
pub struct Trace {
    pub id: u64,
    pub t_press: Option<Instant>,    // PTT 按下；VAD 模式为起始语音帧
    pub t_release: Option<Instant>,
    pub t_vad: Option<Instant>,      // 尾点判定完成
    pub t_asr: Option<Instant>,      // ASR 完成（含结果长度）
    pub t_correct: Option<Instant>,  // 纠错完成（含 skipped 标记）
    pub t_inject: Option<Instant>,   // 注入完成
    pub e2e_ms: u32,                 // t_press(或语音起点) → t_inject
    pub outcome: Outcome,            // Injected | Cancelled | Dropped | Failed
    pub dropped_segments: u8,        // 无效音频段数
    pub fillers_removed: u8,
    pub correction_skipped: bool,
}
```

```markdown
# 静音切分与无效段过滤
覆盖 Silero VAD 的调用方式、双阈值参数、无效段判定与段重组策略。
## 运行位置
VAD 在 **Rust 侧直跑**（ort 加载 silero_vad.onnx），30ms 块单次 <1ms。MUST NOT 移入 Python（违反 latency-budget 分工）。
## 双阈值滞回
| 参数 | 默认 | 说明 |
|---|---|---|
| start_prob | 0.5，连续 3 帧 | 进入说话态（防瞬态噪声） |
| end_prob | 0.35，连续 8 帧 | 判定静音，即尾点 |
| min_speech_ms | 250 | 短于此整段丢弃（咳嗽/键盘声） |
| merge_gap_ms | 200 | 段间隙小于此 MUST 合并（防拆字） |
| pad_ms | 60 | 保留段两侧缓冲（防切掉爆破音字头/尾） |
## 处理顺序
1. 逐块推理 speech_prob
2. 滞回切分出候选段
3. 丢弃：时长 < min_speech_ms 或 段内 RMS < 静音阈值
4. 合并：gap < merge_gap_ms 的相邻段
5. 每个保留段打 pad_ms 缓冲
6. **重组为单条 PCM 送 ASR**（保持上下文，只推理一次）
禁止逐段独立识别——会拆散词语且增加推理次数。
## 停顿换行（可选，默认关）
段间静音 > `postprocess.pause_newline`（默认 1.2s）记为分段点；该模式改为分段并行推理（延迟取最慢段），拼接时在分段点插入换行。
## 埋点
每段处置结果计入 Trace.dropped_segments；丢弃计数上报统计页。
```

```markdown
# TextPostProcessor：文本清理
ASR 输出到纠错之间的文本级清理。纯 Rust、正则实现，≤200 字耗时 <1ms。词表存放 `resources/postprocess/`。
## 五步管线（顺序固定）
```rust
// crates/ime-post/src/lib.rs
let t = filter_hallucination(raw)?;  // 1 命中→None，管线终止
let t = collapse_repeat(t);          // 2
let t = remove_fillers(t)?;          // 3 可能整句清空→None
let t = normalize(t);                // 4
let t = final_check(t)?;             // 5 空/全标点→None
```
返回 `None` 时：不注入，播放短促提示音，Trace.outcome=Dropped。
## ① 幻觉黑名单
整句正则匹配（锚定 ^$）：“谢谢观看”、“字幕由.*提供”、“请不吝点赞.*” 等，词表 `hallucination.txt`。命中即丢弃。
## ② 重复折叠
单字符连续 >`repeat_limit`(默认 8) 次折叠为 2 次。注意“哈哈哈哈”≤8 次是真实表意，MUST NOT 处理。
## ③ 语气词三级清理
| 层级 | 范围 | 词表 | 默认 |
|---|---|---|---|
| L1 句首 | 字符串开头 | 嗯/嗯嗯/呃/啊/诶/哎/唔/噢/emmm/uh/um | ✅ |
| L2 句中孤立 | 前邻句首或标点、后邻标点的孤立填充词 | 同上 | ✅ |
| L3 句尾助词 | 句尾 | 呀/呢/吧/啦/哦/啊 | ❌（改语气，仅深度模式） |
配置 `filler_level = off | standard(L1+L2) | deep(L1+L2+L3)`。
实现约束：
- 删除位置 MUST 满足 `(^|[，。？！、\s])词([，。？！、\s]|$)`，循环至不动点
- 含 CJK 判定：英文输出（无 CJK）MUST 跳过本步骤（"er/um" 在英文是正常词）
**话语标记（那个/就是/然后）不进词表**——可能是实词（“把那个文件给我”），交给 L1 纠错 prompt 处理。
## ④ 归一化
中英文间补空格、连续标点去重、句末标点 `final_punct = keep|strip`、ITN 开关（跟随 ASR 配置）。
## ⑤ 终检

- 模型：Qwen2.5-0.5B GGUF Q4_K_M，llama-cpp-python，temperature=0

ASR原文：{text}
输出：
```

## `docs/03-core-concepts/injection.md`
```markdown
# 光标注入
文字落入光标位置的实现。核心：键盘事件天然落在前台焦点 caret 处，因此只需保证（a）用键盘事件（b）注入瞬间焦点仍是原窗口。
## 焦点快照与恢复
```
按下热键时刻:  快照 {hwnd, pid, tid, title, class, elevated, is_console}
注入时刻:      GetForegroundWindow() == snapshot.hwnd ?
               ├─ 是 → 注入
               ├─ 否 + restore_focus → ALT 技巧恢复焦点后注入
               └─ 否 + !restore_focus → 放弃 + Toast（防串窗）
```
## 策略
| 策略 | 实现 | 适用 |
|---|---|---|
| Unicode（默认） | SendInput + KEYEVENTF_UNICODE，UTF-16 码元逐发，32/块，块间 5ms | 浏览器/Office/微信/Electron |
| Clipboard | 备份剪贴板→写入→Ctrl-V→>500ms 后恢复 | 控制台、>500 字、游戏 |
| Auto | class 匹配 ConsoleWindowClass/CASCADIA_HOSTING_WINDOW_CLASS/mintty 或全屏 → Clipboard，否则 Unicode | 默认 |
换行用 `VK_RETURN`，MUST NOT 发送 Unicode \n。
## 边界情况
| 场景 | 行为 |
|---|---|
| 焦点已切走 | 按 restore_focus 配置恢复或放弃+Toast |
| 提权窗口 | 检测 elevated → 提示以管理员重启；UIPI 静默失败 MUST NOT 发生（发送前校验） |
| Raw Input 游戏 | Auto 判全屏走剪贴板；仍失败 → 文本置剪贴板 + Toast |
| 空结果 | 不注入 + 提示音 |
## 验收用例（injection tests）
记事本 / Chrome 地址栏 / 微信输入框 / Windows Terminal / VSCode 各注入中英文+emoji（😀 验证代理对），断言文本一致且无丢字。
```

## `docs/05-gotchas.md`
```markdown
# 坑位清单
改相关模块前必读。每条含触发条件与对策。
## G1 PyO3 / GIL
- Python 解释器 MUST 固定在推理线程初始化，禁止跨线程使用
- GUI 与核心分进程是刻意的：Python 崩溃（如 llama.cpp segfault）MUST NOT 拖死输入功能
## G2 UTF-16 代理对
- SendInput 按 UTF-16 码元发送。emoji（😀=2 码元）按字符发送会乱码。用 `text.encode_utf16()` 而非 `chars()`
## G3 剪贴板恢复时序
- Ctrl-V 模拟键 MUST 在 SetClipboardData 完成后 ≥30ms 发出，否则粘贴旧内容
- 恢复剪贴板 MUST 延迟 ≥500ms 且可配置关闭（否则目标应用读不到）
## G4 VAD 段边界
- 丢弃段两侧 MUST 留 60ms 缓冲，否则字头爆破音被切导致误识别
## G5 语气词正则
- 中文填充词清理 MUST 仅作用于含 CJK 的输出（英文 "er/um" 是正常词）
## G6 焦点恢复
- SetForegroundWindow 受系统限制：标准解法是先模拟 ALT 键按下/释放再调用。直接调用会随机失败
## G7 提权窗口
- 目标窗口 elevated 而本进程非提权：SendInput 被 UIPI 静默吞掉。MUST 注入前检测并在 UI 提示，禁止静默失败
## G8 首包冷启动
- onnxruntime 首次推理 + llama.cpp 首次 decode 各有 500ms+ 开销。MUST 启动 warmup，否则首次输入必超 1.5s
## G9 量化后标点丢失
- int8 量化若 tokens/前端文件版本不配套，会出现无标点。导出后 MUST 跑 smoke_test 对比
## G10 幻觉
- 静音/噪声输入下 SenseVoice 可能输出“谢谢观看”类幻觉。MUST 在 postprocess 黑名单整句过滤，且空结果不注入
```

## Trace JSON Schema（`trace.finished` 事件与历史行共用）
​```json
{
  "id": 1042,

​```
字段约束：

## SQLite
路径 `%APPDATA%/Xifeng/stats.db`，WAL 模式，schema_version 存 `kv` 表。
​```sql
CREATE TABLE history (
  id INTEGER PRIMARY KEY,
  ts TEXT NOT NULL,
  app TEXT,
  mode TEXT NOT NULL,
  outcome TEXT NOT NULL,
  e2e_ms INTEGER NOT NULL,
  ms_vad INTEGER, ms_asr INTEGER, ms_post INTEGER, ms_correct INTEGER, ms_inject INTEGER,
  speech_ms INTEGER,
  dropped_segments INTEGER NOT NULL DEFAULT 0,
  chars INTEGER,
  fillers_removed INTEGER NOT NULL DEFAULT 0,
  correction_skipped INTEGER NOT NULL DEFAULT 0,
  injection_strategy TEXT,
  raw TEXT, cleaned TEXT, corrected TEXT,
  feedback INTEGER                          -- 1 | -1 | NULL
);
CREATE INDEX idx_history_ts ON history(ts);
CREATE INDEX idx_history_outcome ON history(outcome);
CREATE TABLE kv (key TEXT PRIMARY KEY, value TEXT NOT NULL);
​```
- 写入：每次管线结束同步写（WAL 下 <1ms）。写库失败 MUST NOT 影响注入流程，仅记 error 日志
- 清理：行数超 `stats.history_limit` 时删最旧；每次启动执行 `PRAGMA wal_checkpoint(TRUNCATE)`
- 迁移：schema 变更 MUST 写 `migrations/NNN_*.sql`，按 schema_version 顺序执行，禁止直接 ALTER 旧库
## 统计口径（GUI 唯一真源）
| 指标 | 口径 |
|---|---|
| P50 / P95 | 当日 `outcome=Injected` 的 e2e_ms 分位数；Cancelled/Dropped/Failed 不计入 |
| 识别次数 | 当日全部 outcome 行数（含取消） |
| 今日字数 | Injected 行 chars 求和 |
| 拦截次数 | outcome=Dropped 行数（含幻觉、纯语气词、无效音频） |
| 失败次数 | outcome=Failed 行数 |
| 注入成功率 | Injected / (Injected + Failed) |
| 语气词剔除 | fillers_removed 求和 |
| CPU / 内存 | service + python 进程 10s 采样窗口均值 |

# 产品意图
Xifeng：让任何桌面输入框都能以“按住说话”的速度输入，全程本地，延迟低于打字。
## 目标用户
- 中文长文写作者：聊天、邮件、纪要、工单
- 隐私敏感场景：内网、医疗、法务、离线环境
## 硬指标（不可协商，与验收强绑定）
| 指标 | 值 | 依据 |
|---|---|---|
| 端到端延迟 P95 | < 1.5s | overview/latency-budget.md |
| 数据出境 | 0（唯一例外：模型下载） | overview/architecture.md |
| 输出质量 | 清理+纠错后无需修改整句 ≥ 90%（主观抽测） | acceptance.md M3 |
## 非目标（Non-goals，写进意图防止范围蔓延）
- 不做云端识别、账号体系、联网词库
- MVP 不做流式逐字上屏（句级输出；流式见 Open Questions）
- 不做输入法框架集成（只做 语音→文本→光标注入）
- MVP 平台：Windows 优先，macOS 次之，不做 Linux 承诺
## 设计原则（实现取舍时按序裁决）
1. **Latency-first**：新功能先回答“占多少延迟预算、超了怎么跳过”
2. **Graceful degradation**：每个可能变慢/失败的环节 MUST 有降级路径
3. **Local-first**：断网时除模型下载外全功能可用
4. **Feedback loop**：用户 👎 必须能改变后续行为（词表覆盖/混淆集/负样本）
## 功能意图表

### `docs/10-process/branching.md`
```markdown
# 分支与版本策略
## 分支模型（轻量 trunk-based）
​```
main          ── 受保护：PR + CI 绿才可合入，始终可发布
feature/<slug> ── 短命分支（≤1 周），rebase 合入
hotfix/<ver>  ── 从 tag 拉出，修复后双合（main + 回填）
​```
## 版本语义（SemVer）
- `MAJOR`：IPC 协议/Trace schema 不兼容变更、配置键删除
- `MINOR`：新功能、配置项新增、schema 可选字段
- `PATCH`：修复、词表更新、文档
- 0.x 阶段：MINOR 允许破坏性变更，MUST 在 changelog 标注迁移方法
## 发布流
tag `vX.Y.Z` → CI 构建 → 冒烟 → GitHub Release。main 上每次合入跑 `just check`；夜间跑基准与 `--ignored` 用例。
## 提交规范
`<type>(<scope>): <subject>`，type ∈ feat/fix/docs/test/refactor/perf/chore。scope 用 crate 名或 gui/docs。changelog 由 CI 按 commit 生成，禁手改。
```

# 运行期监控（本地优先）
覆盖日志、健康指标、阈值提示。**无云端上报**——一切遥测留在本机，用户手动导出。
## 日志
- 框架：tracing。级别 `error/warn/info/debug`，默认 info，GUI 关于页可临时开 debug
- 位置：`%APPDATA%/Xifeng/logs/xifeng.log`，按天滚动，保留 7 天，单文件 ≤10MB
- 规则：日志 MUST NOT 记录用户转写文本全文（隐私），只记长度与 outcome；调试期临时例外需 config 开关且默认关
## 健康指标（GUI 统计页“运行状态”区扩展）
| 指标 | 来源 | 提示阈值（GUI 黄标） |
|---|---|---|
| service 进程存活 | IPC 心跳 3s | 断连 → 红标 |
| 注入成功率（滑动 50 次） | metrics.md 口径 | < 95% |
| 推理失败率 | outcome=Failed / 总数 | > 2% |
| e2e P95（当日） | SQLite | > 1500ms 持续 10 分钟 |
| 下载校验失败 | ime-registry | 立即 error |
## 崩溃转储
- ime-service panic → 写 `logs/last_panic.txt`（backtrace + 版本 + 最近 Trace id，无用户文本）
- GUI 崩溃由 WebView 原生机制处理；service 独立存活，输入不中断（架构保障）
- 用户反馈问题时“导出诊断包”按钮：打包 config.toml（脱敏）+ 日志 + 最近 Trace JSON，不含音频与转写内容
```

# 事故响应
## 分级与响应
| 级 | 定义 | 例 | 响应 |
|---|---|---|---|
| S1 | 输入功能不可用/崩溃循环 | service 启动即崩、PyO3 初始化失败 | 立即：hotfix 分支 → PATCH 发布（≤48h）；临时方案写 FAQ |
| S2 | 功能降级但可用 | 纠错全部跳过、剪贴板路径失效 | 评估后 MINOR/PATCH，≤2 周 |
| S3 | 体验问题 | 悬浮窗遮挡、日志噪音 | 排入常规迭代 |
## 流程
1. 定位：按 monitoring.md 指标 + last_panic.txt + 复现步骤
2. 修复：走 hotfix 分支（branching.md），S1/S2 修复 MUST 附回归用例（新 T-*）
3. 复盘：S1/S2 MUST 出 postmortem，存 `08-acceptance/records/incidents/<date>-<slug>.md`，含：时间线/根因/影响面/行动项（行动项进 issue 并关联 RTM）
## 常见预案（预先写好，触发即执行）
| 症状 | 首选动作 |
|---|---|
| 启动即崩（Python 路径） | 检查 runtime/python 完整性 → 文档 G1 → 提供"禁用 LLM 模式"启动参数 |
| 注入全部失败 | 引导切换 clipboard 策略 → 检查提权（G7） |
| 延迟突然超标 | 查最近模型切换记录 → 回退上一模型（registry 保留上一 active 的 sha256） |
