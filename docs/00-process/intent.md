# Intent: VoiceIME — 本地语音输入法（M0 起步）

Author: owner  
Status: draft → 待 G0 批准  
Date: 2026-10-28

## Problem

现在在这台 Windows 机器上，把"想到的话"变成文字只有两条路：

1. 打字 —— 中文长句输入速度被键盘和输入法候选框卡住；
2. 云端语音输入 —— 转写文本会离开本机，且断网不可用。

现有输入法没有"按住说话、松开出字、落在光标处"的本地能力。

## Proposed outcome

一个常驻本地的 Windows 程序：按住 Ctrl 说一句话，松开后 1.5 秒内，文字出现在**当前光标位置**。全程不联网（唯一网络请求是首次下载模型）。

M0 只验证一件事：**这条链路能不能端到端跑通，并且延迟数字是可信的。**

## Affected users and systems

- 用户：我自己（中文长文/聊天/纪要场景）
- 系统：Windows 10/11 x64；任意前台输入框（记事本、浏览器、IDE、聊天软件）
- 依赖：麦克风、SenseVoice ONNX 模型、Silero VAD 模型

## Constraints

- **延迟**：端到端 P95 ≤ 1500ms（按下热键 → 文字出现在光标处）
- **本地**：音频与文本不得离开本机
- **不抢焦点**：注入不得改变前台窗口；焦点已切换时按配置放弃或恢复
- **零配置可用**：默认热键、默认模型，装完即可说话
- **技术路线**：Rust 核心（音频/VAD/注入）+ Python 推理（ASR/纠错）+ Tauri GUI（M3 之后）
- **M0 范围**：不带 GUI、不带纠错 LLM、不带模型热切换

## Non-goals（M0 明确不做）

- 不做流式逐字上屏（句级输出）
- 不做中文以外的语种优化
- 不做输入法框架（IME）集成，只做"语音 → 文本 → 光标注入"
- 不做账号、云同步、联网词库
- 不做 macOS / Linux
- 不做自动更新、代码签名（M4 才需要）

## Open questions

1. ~~这台机器 8 核 CPU 上 SenseVoice int8 的真实 RTF 是多少？~~ → **已回答**：4.49s 音频、8 线程，空载 P50 329ms / P95 355ms（RTF≈0.073）；带载 ~53% 时 485/648ms。见 `01-overview/latency-budget.md`。
2. ~~SendInput `KEYEVENTF_UNICODE` 在微信 / Windows Terminal / VSCode 里的实际成功率？~~ → **部分回答**：同进程 Tk 窗口 5/5（中文、混排、emoji、换行、184 字）。**跨进程应用（微信/Windows Terminal/VSCode）仍待人工验证。**
3. 麦克风采集用 16k 直采还是 48k 重采样？取决于 cpal 在该设备上的可用配置。
4. 是否需要 VAD？M0 先用"按键起止"，VAD 在 M1 引入。

## Success criteria（M0 验收）

| # | 判据 | 验证方式 |
|---|---|---|
| S1 | 连续 10 次"按住→说话→松开"，≥9 次在记事本中正确出字 | 手动 |
| S2 | 每次输入都有 Trace，含各阶段耗时与 e2e | 日志/统计输出 |
| S3 | e2e P95 有真实数字（不设门槛，先有数） | bench 输出 |
| S4 | 无网络时除模型下载外全流程可用 | 断网跑一次 |

> M0 不追求 1.5s 达标。**先有链路，再有数字，再有优化。**
